# Contributing to bhamranked

Audience: Owen (solo author) plus any future collaborator. Format mirrors the
"2 hrs/week, no friction" cadence the project is designed around.

## The 11-step publish pipeline

Every piece moves through these stages. Steps 2-6 produce drafts in
`content/drafts/{slug}.mdx`; step 7 promotes the draft into the Astro content
collection at `src/content/listicle/` or `src/content/feature/`.

| # | Stage              | Who         | What it produces                                       |
|---|--------------------|-------------|--------------------------------------------------------|
| 1 | research           | `bham-researcher`   | `content/research/{topic}.md` dossier of candidates    |
| 2 | scaffold           | `bham-scaffolder`   | `content/drafts/{slug}.mdx` skeleton + frontmatter     |
| 3 | visit (real life)  | Owen        | Photos in `src/assets/photos/{slug}/`, raw notes       |
| 4 | weave              | `bham-weaver`       | Draft prose stitched into scaffold from notes          |
| 5 | polish             | Owen        | Final pass — voice, accuracy, judgment calls           |
| 6 | humanizer          | `/humanizer`        | Strip AI tells; keep Owen's voice                      |
| 7 | EEAT audit         | `bham-eeat-auditor` | Verify visit_date, photos, schema, disclosure          |
| 8 | site-architect     | `bham-site-architect` | Move draft → `src/content/`, wire routing, schema check |
| 9 | schema + SEO check | (automated) | `npm run build` → `npm run test:once` → all green      |
|10 | ship               | `/ship` or `git push` | Pushes to main; CF Pages auto-builds; IndexNow pings |
|11 | live QA            | `/qa`       | Smoke the live URL, validate Rich Results, OG previews |

## Pre-publish manual smoke checklist

Run after `npm run build` succeeds locally and before pushing:

- [ ] `npm run dev` — open http://localhost:4321 — masthead, theme toggle, all category links resolve
- [ ] Submit the newsletter form once; confirm Beehiiv success page renders
- [ ] Toggle dark mode; refresh; persists across navigation
- [ ] Mobile breakpoints: resize to 375px, 768px, 1024px — no horizontal scroll, no overlap
- [ ] Validate the piece in Google's Rich Results Test: https://search.google.com/test/rich-results
- [ ] Validate the OG image in Twitter Card Validator: https://cards-dev.twitter.com/validator
- [ ] Validate the OG image in Facebook Sharing Debugger: https://developers.facebook.com/tools/debug/
- [ ] Lighthouse desktop on the homepage and the new piece: P/A/BP/SEO each ≥ 95
- [ ] After deploy: Cloudflare Web Analytics shows the new URL within 5 minutes of first traffic

## Publish workflow (the live edit)

Most "publish" actions are a frontmatter edit and a `git push`:

```bash
# 1. Flip the `published` field from null → today's date in the MDX file:
#    src/content/listicle/<slug>.mdx
#    published: 2026-05-20
#
# 2. Build + test locally
npm run build
npm run test:once

# 3. Commit + push
git add -A && git commit -m "Publish: <slug>" && git push origin main

# 4. Cloudflare Pages auto-builds within ~90s.
# 5. POST /indexnow on the live host to ping Bing/Yandex/etc:
curl -X POST https://bhamranked.com/indexnow
```

To take a piece down, set `published: null`, push, redeploy.

## Content schema validation

Astro + Zod validate every MDX frontmatter at build time via
`src/content/config.ts`. The "test" is implicit: `npm run build` fails if a
required field (e.g. `visit_date`, `address`, `disclosure`) is missing or
mistyped. Don't add a standalone test for this — it's redundant with the
build gate, and removing the build gate would mean removing strict mode (no).

## Trust-pages input queue (Owen-side, deferred)

Voice-bearing copy on these pages is intentionally left as `[OWEN INPUT NEEDED]`
markers. The site-architect agent will never invent first-person prose. Items:

- `/about` — Owen's bio, Bellingham residency context, food background, photo
- `/about` — `sameAs` URLs in `src/lib/schema.ts buildPersonSchema()` (LinkedIn, Twitter/X, Instagram, personal site)
- `/editorial-policy` — ranking-criteria narrative in Owen's words
- `/methodology` — visit-process detail (already partly drafted; verify)
- `/contact` — editorial vs. advertising contact paths
- `og-default.png` — regenerate via `node scripts/build-og-default.mjs` after any tagline change

## CI gates summary

| Gate                | Where it runs       | Threshold          |
|---------------------|---------------------|--------------------|
| Zod content schema  | `npm run build`     | Build fails on miss |
| EXIF preservation   | `npm run test:once` | All photos have parseable DateTimeOriginal |
| Link integrity      | `npm run test:once` | 0 broken internal links |
| Schema.org validity | `npm run test:once` | Every JSON-LD block parses + has @context + @type |
| Lighthouse          | `.github/workflows/lighthouse-ci.yml` | P/A/BP/SEO ≥ 0.95 |
| axe-core a11y       | Lighthouse a11y category (axe under the hood) | 0 violations |

## Things to NOT do

- Don't add affiliate links to editorial pieces (clean-lanes editorial integrity).
- Don't add analytics scripts other than the configured Cloudflare Web Analytics.
- Don't strip EXIF from photos (it's the strongest E-E-A-T "Experience" signal).
- Don't use AI-flavored vocabulary: `delve`, `crucial`, `robust`, `vibrant`,
  `elevated`, `must-try`, `hidden gem`, etc. Use plain words.
- Don't add `Disallow:` to `public/robots.txt` thinking it "noindexes" a page —
  it just blocks crawling. Use the BaseLayout `noindex` prop instead.
